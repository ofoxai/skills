# Fetch video pricing from the catalog endpoint instead of hardcoded tables

## Goal

Two price tables were hand-copied from model pages two days ago and are already
a liability: `batch_rate_for()`'s 15-line `case` drives the **estimate shown to
users before they spend money**, and `references/pricing.md` is what an agent
reads to quote a cost. Both go wrong silently the moment Ofox changes a price
or a promo ends — and several rates currently on those pages are explicitly
discounted (Seedance 2.0 at 10% off, 2.0-fast at 30%, 2.5's 1080p a
time-limited $0.48 against a $0.60 list). A wrong estimate is worse than no
estimate. The catalog endpoint returns the full matrix for free; read it.

## What I already know

- `GET https://api.ofox.ai/v2/models/catalog/{owner}/{slug}?include=provider_price`
  is **public, keyless and free** (verified live with `OFOX_API_KEY` unset →
  HTTP 200). Already used by this skill for `providers` and `--provider`
  validation, with `load_catalog()` / `catalog_cache_path()` in place and a
  24h cache.
- `provider_cards[].pricing.video_pricing.tiers[]` carries
  `{resolution, input_type, price}` for every combination, e.g.
  `{"resolution":"480p","input_type":"t2v","price":"0.11"}`, plus a
  resolution-less entry that is the "all other combinations" catch-all.
- Prices were verified identical across `byteplus` and `volcengine` for
  seedance-2.5, but that is a fact about today, not a guarantee. When a job is
  pinned to a provider, the estimate should read that provider's card rather
  than assuming parity.
- Billing mode: **image-to-video bills at t2v rates**; v2v rates apply only
  when a *video* is the input. Confirmed by a real i2v run billing
  4s × $0.11 = $0.44 at 480p. So the estimate picks the `v2v` tier only for
  video input, `t2v` otherwise.
- `/v1/models` gives each model's `default_resolution`, which is what the API
  uses when `--resolution` is omitted — better than `batch_rate_for`'s current
  hardcoded `720p` assumption.
- Current hardcoded state: `ofox-video.sh:1152` (`batch_rate_for`, 15 case
  arms) and `references/pricing.md` (13 table rows).
- `generate` does **not** currently estimate at all — only `batch` does. The
  scenario skills tell the agent to quote a cost from `pricing.md` by hand,
  which is exactly the table being retired.

## Decisions (mine)

- **Same fallback ladder as everything else here**: fresh cache → live fetch →
  stale cache → bundled snapshot → no estimate. The last rung keeps today's
  behavior (say the estimate is unavailable rather than invent one), because a
  missing price must never block a generation.
- **A price we cannot verify is not printed.** No guessing, no stale constant
  presented as current. `batch_rate_for`'s conservative "print nothing when
  unsure" behavior is preserved, just with better sources.
- **`generate` gains an estimate too.** Same function, no extra cost, and it
  removes the reason a scenario skill would hand-compute from a table we are
  deleting. The estimate goes to stderr so it can't corrupt the `KEY VALUE`
  stdout contract.
- **`pricing.md` keeps a human-readable table**, clearly stamped as a
  point-in-time snapshot, with the live command (`ofox-video.sh providers`)
  named as the source of truth. Deleting it outright would lose the
  cheap-vs-expensive narrative that makes the gacha workflow make sense; the
  fix is to stop treating it as authoritative, not to remove the explanation.
- **The estimate reads the pinned provider's card** when a provider is pinned,
  falling back to the first card otherwise.

## Requirements

1. Replace `batch_rate_for()` with a catalog-backed lookup keyed on
   (model, resolution, mode, provider), returning nothing when unknown.
2. Default the resolution to the model's `default_resolution` from
   `/v1/models` rather than a hardcoded `720p`.
3. Pick the `v2v` tier only when a video is the input; `t2v` otherwise
   (image-to-video bills at t2v).
4. Bundle a `pricing-snapshot.json` fallback, regenerated by the existing
   `refresh-snapshot.sh`.
5. Add a pre-flight estimate to `generate` (stderr), matching `batch`'s
   wording, and never printing an unverified number.
6. Rewrite `references/pricing.md`: keep the ladder narrative and a dated
   snapshot table, point at `providers` for live numbers, and state plainly
   that the script no longer reads this file.
7. Update the scenario skills' cost guidance to use the script's own estimate
   instead of hand-computing from the table.
8. Tests, free by construction, in the shape of the existing suites.
